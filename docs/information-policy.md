# 정보의 흐름

PickEatUp이 어떤 정보를 어디서 처리하고, 어디에 얼마나 두고, 누구에게 전달하는지 한 표로 모았습니다. 각 결정의 이유는 해당 사례에 있습니다. 기준일은 2026년 10월 3일(한국 시간)이고, 구현으로 확인한 사실입니다.

## 원칙

- **필요할 때만 묻습니다.** 위치 권한은 앱에 들어올 때가 아니라 근처 식당을 찾을 때 묻습니다.
- **정한 것만 남깁니다.** 고르는 중인 것은 화면에만 두고, 정한 결과만 이 기기에 남깁니다.
- **로그인 없이 씁니다.** 계정이 없어서 기록은 기기(브라우저)에만 남습니다. 그래서 화면에 "이 기기에만 저장돼요"와 '기록 지우기'를 함께 보여줍니다.
- **서버에 저장하지 않는 것과 외부로 보내지 않는 것은 다릅니다.** 둘을 나눠서 적습니다.

## 권한

- **위치:** '지금 있는 곳'을 누르거나, 이미 허용한 브라우저에서 검색할 때만 씁니다. 거부하면 역 이름이나 주소로 입력합니다.
- **클립보드:** 사용자가 '복사'를 누를 때만 씁니다.
- **공유:** 휴대폰에서 사용자가 '공유'를 누를 때만 공유 창을 엽니다.

## 아직 정하지 않은 것

- 로그인이나 행동 분석 도구(예: GA4)를 붙이게 되면, 개인정보 처리방침을 따로 만들고 이 표를 다시 봅니다.
- 카카오 가게 정보를 서버에 둬야 하는 기능(예: 식당 링크를 짧게)은, 카카오 운영정책을 확인한 뒤에 다시 판단합니다.
