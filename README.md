# PickEatUp

**매일 하는 고민, 조금 더 가볍게.**

메뉴를 떠올리고, 함께 갈 식당과 만날 곳을 제안하고, 누가 정할지 고르는 수고를 덜어주는 웹앱입니다.

**[앱 사용하기 →](https://pickeatup.vercel.app)** · [제품과 개선 기록](docs/README.md) · [만든 사람](https://github.com/haesolhong)

## 일상에서 반복되는 선택의 부담을, 조금 더 가볍게 만들 수 있을까?

금융업에 종사하면서, 일반 소비자인 고객이 정보를 찾고 이해하고 선택하는 과정에서 겪는 불편에 관심을 가져왔습니다. 정보의 차이나 복잡한 절차 때문에 고객이 많은 시간과 노력을 들여야 하는 상황을 보며, 그 수고를 서비스와 프로세스 차원에서 줄여보고 싶었습니다.

이러한 경험은 제가 PM으로서 만들고 싶은 제품의 방향으로 이어졌습니다. 사용자가 원하는 일을 더 쉽게 하고, 자신에게 중요한 일에 집중할 수 있도록 돕는 제품입니다. 필요한 정보를 이해하기 쉽게 전달하고, 불필요한 선택과 절차를 덜어내면서, 사용하는 사람이 배려받는다고 느낄 수 있는 친절함도 담고 싶습니다.

**PickEatUp은 그 관점을 ‘오늘 뭐 먹지?’라는 익숙한 고민에 적용해본 개인 프로젝트입니다.** 평소 직접 겪던 고민에서 출발해, 메뉴를 떠올리고 함께할 사람을 고려하며 먼저 제안하는 과정의 부담을 줄이고자 했습니다.

처음에는 가장 필요하다고 느낀 **‘오늘 뭐 먹지?’에 순대국밥, 김치찜처럼 구체적인 메뉴 하나를 제안하는 작은 MVP**로 시작했습니다. 직접 사용하고 주변 사람들과 나누면서 필요한 상황과 다음 행동을 발견하고, 이를 사용 시나리오와 사용자 흐름으로 구체화하며 실제로 동작하는 웹앱으로 구현해 배포하고 있습니다.

현재는 직접 겪은 불편과 소수 지인의 요청·반응을 바탕으로 기능과 UX를 조금씩 수정하고 보완하는 단계입니다. 작은 경험에서 개선할 문제를 찾고, 무엇을 먼저 해결할지 판단하며 기획과 구현을 함께 발전시키고 있습니다.

## 어떤 순간에 쓰나요?

| 이런 순간에 | 기능 | 제공하는 도움 |
| --- | --- | --- |
| 먹고 싶은 메뉴가 떠오르지 않을 때 | 오늘 뭐 먹지? | 취향을 고르거나 바로 구체적인 메뉴 하나를 추천받습니다. |
| 함께 있는데 어디서 먹을지 막막할 때 | 오늘 어디서 먹지? | 기준 위치 근처의 식당 후보를 살펴보고 한 곳을 정합니다. |
| 서로 결정을 미루고 있을 때 | 오늘 누가 정해? | 함께할 사람 중 결정권자 한 명을 뽑습니다. |
| 만날 동네를 먼저 제안하기 어려울 때 | 오늘 어디서 만나? | 서울 주요 만남 거점 중 한 곳을 제안받습니다. |

‘오늘 뭐 먹지?’가 메인입니다. 여럿이 쓰는 질문은 작은 **‘여럿이라면’** 진입점 아래에 모았습니다. 처음부터 사용 상황을 추가로 선택하게 하기보다, 필요한 기능으로 들어갈 수 있도록 구성했습니다.

## 제품을 만들며 생각하는 것

- **떠올리고 제안하는 수고를 줄입니다.** 필요한 만큼의 후보를 제시해 다음 행동을 시작할 수 있도록 돕습니다.
- **입력과 선택에도 비용이 있다고 생각합니다.** 꼭 필요한 질문부터 묻고, 조건을 고르지 않아도 시작할 수 있게 합니다.
- **기능은 정해주는 대상과 상황을 기준으로 나눕니다.** 메뉴·식당·사람·동네를 구분하고, 같은 결정을 돕는 옵션은 기존 기능 안에서 다룹니다.
- **결과 이후의 행동까지 생각합니다.** 확인, 결정, 공유, 다시 보기로 이어지는 흐름에서 반복 입력과 설명의 수고를 줄이고자 합니다.
- **정보의 흐름도 사용자 경험의 일부로 봅니다.** 기능에 필요한 정보, 저장되는 정보, 공유되는 정보와 실패 상황을 함께 설계합니다.

## PM의 판단을 실제 서비스로 옮기는 과정

개선 기록은 **문제 발견 → 사용자 가치 → MVP 범위 → 선택과 이유 → UX/UI → 정보·운영 정책 → 구현·비용 → 검증과 다음 단계**의 흐름으로 정리합니다.

추천 규칙, 외부 API, 저장 방식, 화면 구성도 해당 사용자 상황을 해결하기 위해 내린 선택으로 설명합니다. 자세한 소스 대신 구조와 판단 근거를 공개합니다.

현재 문서는 프로젝트 소개와 기록 체계를 먼저 마련한 버전입니다. 주요 개선 사례와 대표 화면은 확인된 자료를 바탕으로 순차적으로 추가합니다.

→ [어떤 개선을 기록할지 보기](docs/README.md)

## 기술 구성

| 구성 | 사용하는 곳 |
| --- | --- |
| Next.js · React · TypeScript | 웹 화면과 서버 API 구현 |
| Kakao Local API | 근처 식당과 위치·역 검색 |
| Upstash Redis | 공개 방명록 저장 |
| PWA · Service Worker | 설치와 일부 오프라인 경험 |
| Vercel | 웹앱 배포 |

설치·오프라인 지원 범위, API 선택 이유와 제약, 비용이 발생하는 지점은 관련 개선 사례에서 구체적으로 다룹니다. 실제 지출과 무료 제공 범위는 확인한 시점을 기준으로 구분해 기록합니다.

## 현재 단계

- 작은 MVP에서 시작해 배포와 개선을 이어가는 개인 프로젝트입니다.
- 직접 사용한 경험과 소수 지인의 피드백을 바탕으로 개선하고 있습니다.
- 사용자 가치에 대한 가설과 실제 확인한 반응·동작을 구분합니다. 인지 부담 감소나 광범위한 이용 패턴을 검증한 성과로 제시하지 않습니다.
- 식당 추천은 현재 점심 상황을 중심으로 하며, 만날 곳 제안은 서울의 선정된 거점이 대상입니다. 개인별 이동시간을 계산하는 기능은 아직 제공하지 않습니다.
